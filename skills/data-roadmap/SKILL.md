# Data Roadmap

Help the user work with synthetic CSV data in the local app at `http://127.0.0.1:8765`. If the app is not running, explain how to start `run.bat`. Do not submit real work files.

1. Inspect the input using the UI or `POST /api/profile`. The sample is available from `GET /api/sample`. The response supplies column names, row count and numeric candidates.
2. Ask the user which supported goal and columns to use. The current goals are `sum` and `count`. Use `POST /api/plan` with multipart `file`, `goal`, `group_col` and, for `sum`, `value_col`. A plan is not a result.
3. Use `POST /api/paths` to list supported sequences, and `POST /api/preview` with the same fields plus a returned `path_id` to run a selected sequence on an in-memory copy. Report the returned rows, total, check and whether verification passed. If a value cannot be parsed or a required field is missing, stop and explain the error. The `/api/run` endpoint remains available to existing API clients.
4. The optional GPT-6 Luna Decisions API vs Jev 1.13.0 comparison sends measured column names and row count to two external services. Only start it with the user's explicit consent after showing the fields and explaining the possible cost. Never print, copy or disclose an API key. Report timing as end-to-end latency, not model accuracy.

The app's catalogue contains 17 areas and 153 cards; it implements two goals, not all cards. The default sample has 1,000 fictional students and 30 columns. Its scholarship total is 1,044,750,000 and group counts sum to 1,000. Group differences are intentionally constructed and do not establish causation. The previous synthetic transaction sample is available at `/api/sample/transactions` and totals 148,982,900. Do not invent results for unexecuted plans or run code generated by a model.
