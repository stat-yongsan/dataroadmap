# Codex 앰버서더 지원서 초안

[코덱스] 2026-10-25 작성. 현재 구현 실적과 OpenAI 연결 계획을 구분한 문안이며, 아래 본문에는 Jev를 넣지 않았다.

[클로드] 2026-10-25 고침([나] 「고칠 4곳 고쳐줘」): ①프로토타입을 만든 도구(Claude Code)를 사실대로 적고, Codex는 다음 단계(D23 · T15 · T16)로 구분 ②정보 부족 · 미지원 멈춤은 이미 구현된 기능이라 현재형으로 ③predicate는 코드의 noul처럼 17개 작업 영역 단위 판단으로 ④Astra = OpenAI GPT-6 Astra로 밝힘 — [나] 26.10.25 「Astra 맞아」로 확인.

**원자료를 검증 가능한 분석 경로로 바꾸는 ‘데이터 활용 로드맵’**

저는 엑셀 실무자가 원자료에서 필요한 결과를 얻는 과정을 재사용 가능한 작업으로 나누고, 처리 경로와 검증 근거를 함께 보여 주는 데이터 활용 로드맵을 연구·구현하고 있습니다. OpenAI GPT-6 Astra를 활용해 정리한 17개 작업 영역·153개 세부 작업 카드를 바탕으로, 파일 읽기부터 정제·집계·차트·HTML 결과 생성까지 연결하는 로컬 프로토타입을 Claude Code로 만들었습니다.

**1. 입력 데이터**

입력은 엑셀·CSV 원자료와 사용자가 정한 분석 목적입니다. 부서별 지출 합계, 중복을 제외한 인원 수, 그룹별 비율처럼 실무에서 반복되는 질문을 다룹니다. 한 행이 의미하는 대상, 중복을 판단할 업무 키, 금액 단위 등 계산에 필요한 정보도 함께 확인합니다. 시연에는 거래번호·부서·사용처·금액으로 구성한 1,000행 가상 지출 자료를 사용했습니다. ‘98,300원’처럼 숫자가 문자로 저장된 사례를 포함해 정제부터 집계까지 검증했습니다.

**2. 처리 과정**

먼저 코드가 표의 구조, 자료형, 누락값, 중복 키를 조사합니다. 이어 17개 작업 영역 중 분석 목적과 관련된 후보를 찾고, 각 작업의 필수 입력·실행 조건·구현 여부를 확인해 실행 가능한 경로를 구성합니다. 현재 프로토타입은 명시한 규칙과 우선순위로 경로를 제안합니다. 사용자가 선택한 단계를 Python으로 실행하고, 결과를 검증한 뒤 바뀐 데이터 상태를 기준으로 다음 경로를 다시 제안합니다. 필수 열의 존재나 숫자 변환 성공 여부처럼 확정적으로 검사할 수 있는 조건은 코드가 판정합니다. 업무 키나 한 행의 의미처럼 필요한 정보가 부족하면 다음 작업 대신 ‘정보 필요’를, 실행기가 없는 작업이면 ‘지원 안 됨’을 골라 멈추며, 이 동작은 예제 자료로 자동 검사합니다.

이 기반을 Codex와 OpenAI Decisions API를 결합하는 방식으로 확장할 계획입니다. 다음 단계인 Decisions API 연결과 실습용 Skill은 Codex로 구현하고, 그 과정을 기록해 공개합니다. Codex가 분석 절차와 실행·검증 흐름을 다루고, Decisions API는 허용된 후보 중 다음 작업을 고르는 `choice`, 17개 작업 영역 각각이 지금 단계에 필요한지를 영역 단위로 판단하는 `predicate`, 목표에 대한 기여도를 평가하는 `score`를 맡도록 구성합니다. 검증 결과를 다음 판단에 반영하는 구조는 OpenAI가 공개한 Codex의 반복 검토·수정·검증 패턴을 데이터 처리에 적용하는 구상입니다. Decisions API와 Codex 실행 루프의 실제 연결은 후속 구현 단계입니다.

**3. 결과물**

결과물은 처리 경로를 보여 주는 분기 그래프, 그룹별 집계표, 고유 대상 수와 비율 결과, 차트, 필터가 있는 HTML 보고서, 실행 이력입니다. 원자료와 각 단계의 결과를 구분해 보존하고, 실제 실행한 결과와 아직 실행하지 않은 계획을 화면에서 구별합니다. 사용자는 결과 숫자와 함께 어떤 작업을 거쳤고 어느 단계에서 확인이나 추가 정보가 필요한지도 볼 수 있습니다. 현재 153개 카드 중 실행기를 구현한 범위는 12개이며, 전체 작업 카탈로그와 실제 실행 지원 범위를 구별해 표시합니다.

**4. 검증 방법**

검증은 실행 전에 정한 정답과 데이터 보존 규칙을 기준으로 진행합니다. 집계 전후 합계, 행 수, 고유 대상 수, 식별자의 앞자리 0, 분모가 0인 비율, 원본 보존 여부를 확인합니다. 개발기록상 1,000행·10개 부서 지출 시나리오에서 앱 집계 합계 148,982,900원이 독립 계산 결과와 일치했고, 2026년 9월 28일 저장된 자동검사 보고서에는 87개 항목 전부 통과가 기록돼 있습니다. 이는 기존 코드 기능의 검증 결과입니다. Decisions API 연결 뒤에는 정답을 정한 대표 사례로 다음 작업 선택의 적절성, 정보 부족 시 중단 여부, 허용되지 않은 작업의 차단 여부를 별도로 평가할 계획입니다.

이 경험과 Codex로 구현하는 과정을 Codex Skills와 실습 자료로 정리해, 엑셀 실무자가 자신의 업무를 작은 작업으로 나누고 실행 결과를 직접 확인하며 자동화를 확장할 수 있도록 공유하고 싶습니다.
