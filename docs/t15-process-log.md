# T15 과정 기록 — OpenAI Decisions API 공급자 연결

- 기간: 2026-10-31
- 구현: Claude Code(모델 claude-opus-5-5). Codex가 구현한 작업이 아니다. Codex 사용 한도가 소진되어 [나]의 지시로 담당을 바꿨다(devplan D24).
- 상태: 가짜 서버로 검증. **실제 OpenAI 호출은 아직 하지 않았다.**

## 무엇을 만들었나
앱이 묻는 세 가지 판단을 Decisions API 모양으로 옮겨 보내고, 응답을 앱의 기존 검증기로 돌려보낸다.

| 앱 | Decisions API |
|---|---|
| 영역 판단 `noul` | `predicate` → `probability` |
| 기여도 `score`(수준 목록) | `score` + `levels[{label}]` |
| 다음 작업 `choice`(선택지 dict) | `choice` + `choices[{value, description}]` |
| 확률 dict | 확률 목록 `[{value, probability}]` |
| 측정 상태 | `input` 의 `input_json` |

계산 · 조건 검사 · 결과 검증은 그대로 등록된 Python 실행기가 맡는다. 모델은 허용 후보 안에서만 고른다. 실패는 실패로 남고 모의 판단으로 바뀌지 않는다.

## 시작 전에 확인한 것
- 공식 가이드와 API 레퍼런스(2026-10-31): `POST /v1/decisions`, 모델 `gpt-6-luna`, 질문 1~400개, 선택지 2~255개, 수준 2~10개, `input_json` 256 KiB, 응답 최상위 `answers` · `model` · `usage`, 거절 = `type: "refusal"`(사유 칸 없음).
- 앞서 붙인 Codex 공급자는 1/0 선택 표시만 돌려주는 별도 경로다. Decisions API는 실제 분포와 confidence를 돌려주므로 그 분기를 재사용하지 않고 새 공급자 값 `openai` 를 만들었다.

## 판단과 이유
- **거절은 어댑터가 아니라 검증기에서 멈춘다.** 어댑터에서 예외를 던지면 응답 원문을 잃는다. 검증기까지 보내면 기존 「거절 응답 보존」 경로로 토큰 기록이 남고, 변환 전 응답 전체도 함께 남긴다.
- **문서가 보장하지 않는 것은 추측하지 않는다.** `probabilities` 에 모든 선택지가 오는지, `choice` 가 항상 최대 확률인지는 문서에 없다. 기존 검증을 유지해 어긋나면 거절하고 원문을 남긴다. 실제 응답을 본 뒤 다시 판단한다.
- **허용 오차는 바꾸지 않았다.** 지금 값의 근거는 Jev 응답의 반올림이다. OpenAI 응답의 반올림 여부는 모른다. 실호출 표본이 생기면 다시 본다.
- **키가 있어도 저절로 켜지지 않는다.** 사람이 고르고, 보낼 필드를 보고, 동의해야 호출한다.
- **400 계열은 서버가 밝힌 이유를 남기고, 401 은 옮기지 않는다.** 401 문구에는 키 조각이 섞일 수 있다.

## 고치다 찾은 것
- 내보내기의 공급자 표시 함수가 모르는 값에서 `KeyError` 를 내고, 그 오류가 API에서 404 「없는 계획」으로 바뀌었다. 표시 함수를 모르는 값에도 안전하게 고쳤다.
- 화면 곳곳이 「Codex가 아니면 TypeSafe」로 갈라져 있어, 새 공급자의 동의 문구가 틀린 목적지를 가리킬 뻔했다. 표시명을 한 곳으로 모았다.
- 관리자 화면에서 「활용 로드맵 만들기」가 왜 잠겼는지 알려 주는 문구가 없었다. 다음 할 일을 버튼 옆에 표시한다.
- 첫 구현은 응답 값이 문서와 다른 형태(예: 목록)면 파이썬 예외로 계획 생성이 멈췄다. 자체 검토에서 찾았고, 이제 판단 실패로 끝난다.
- 기존 화면 시험 하나는 키가 없는 환경에서 실패했다. 저장점 코드에서도 같았고, 원인은 Playwright `is_disabled()` 가 `<option>` 에 늘 거짓을 돌려주는 것이었다. DOM 값을 보도록 고쳤다.
