# Codex와 함께하는 데이터 활용 로드맵 실습

엑셀 업무를 작은 작업으로 나누고, 실행 결과를 검증한 뒤 다음 작업을 선택하는 방법을 연습합니다. 약 30분. 처음에는 가상 예제와 모의 판단을 사용합니다.

## 준비물

- Windows PC, Python 3.13, Node.js 22와 npm, Codex.
- 이 저장소를 내려받아 `run.bat`을 실행하고 `http://127.0.0.1:8765`에 접속합니다. 자세한 설치는 [README](../README.md)를 참고하세요.
- 공개 [1,000행 예제](https://dataroadmap.axmaster.cloud/)도 볼 수 있습니다. 공개 화면은 저장된 실행 기록을 보여 주며 버튼을 눌러도 모델을 호출하지 않습니다.
- Codex에서 이 저장소를 열고 [data-roadmap Skill](../skills/data-roadmap/SKILL.md)을 참고하도록 요청합니다. 자동으로 설치되었다고 가정하지 마세요.

## 0–5분: 결과와 문제 보기

공개 예제에서 단계 버튼을 눌러 금액 변환, 검증과 최종 집계표를 봅니다. 예제는 거래 1,000건, 부서 10개, 합계 148,982,900원입니다. ‘문자 금액을 계산 전에 왜 바꿔야 하는가’를 서로 설명해 봅니다.

## 5–15분: 로컬에서 계획 만들기

1. 로컬 앱 첫 화면의 **예제 A · 문자 금액을 부서별 집계로**에서 **불러오기**를 누릅니다.
2. 표 범위와 열 측정값을 확인합니다. 목적은 부서별 합계, 그룹 열은 부서, 값 열은 금액, 업무 키는 거래번호, 한 행의 의미는 거래 1건, 단위는 원으로 확인합니다.
3. 판단을 **모의 판단(MOCK)**으로 선택하고 **활용 로드맵 만들기**를 누릅니다. 데이터 준비가 덜 됐다면 화면의 안내에 따라 확인합니다.
4. 그래프의 현재 상태 바로 다음 노드를 열어 선택 이유·실행 조건을 보고, 실행 가능한 단계만 차례로 실행합니다. 각 실행 뒤 새 계획과 검증 결과를 살펴봅니다.

Codex에 아래처럼 요청해 보세요.

> 로컬 데이터로드맵에서 예제 A를 모의 판단으로 살펴봐 줘. 실행 가능한 현재 단계와 필요한 확인을 먼저 설명하고, 실제로 실행한 단계와 아직 계획인 단계를 구분해 줘.

## 15–25분: 정답과 중단 조건 검토

`examples/expected/A.json`의 정답과 최종 합계를 비교합니다. 교과 2,000원, 비교과 500원, 전체 2,500원이어야 합니다. 실행 전 정답을 결과에 맞춰 바꾸지 않습니다.

다음으로 한 행의 의미를 비워 새 계획을 만들고, **정보 필요** 후보와 다른 실행 후보가 어떻게 표시되는지 확인합니다. 예제 A에서는 정보 필요 후보가 나타나더라도 모의 판단이 다른 단계를 추천할 수 있습니다. 어떤 정보가 부족한지 확인한 뒤 진행 여부를 결정하세요. Codex에는 “어떤 값이 실제 실행 결과이고 어떤 값은 아직 계획인지 구분해 설명해 줘”라고 요청합니다.

## 25–30분: 회고와 확장

- 다음 작업 선택과 계산·검증은 각각 누가 담당했나요?
- 데이터 규칙이 잘못되면 어느 단계에서 알 수 있나요?
- 다른 가상자료에 적용한다면 한 행의 의미와 업무 키는 무엇인가요?

선택 활동으로 실제 Codex 판단을 시도할 수 있지만, 먼저 사용자에게 전송될 필드를 보여 주고 동의를 받습니다. 모의 판단 결과를 실제 모델 성능으로 부르지 않습니다. 공개 예제와 로컬 실습에는 실제 업무 파일을 사용하지 않습니다.
